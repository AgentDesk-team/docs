title: "Create and review your first task"
description: "Create through chat or Work Items, review the brief, approve execution, and verify the result."
---

## Create the work item

You can create a task through an agent conversation or directly in **Projects → Work Items → Add work item**. **Add intake item** also starts incoming work in the project's Intake flow.

For a rough request, begin with the Product Owner or another suitable agent:

```text
Create a task in this project to improve our onboarding explanation.
Define scope, expected output, acceptance criteria, and verification.
Keep it in Inbox for my review.
```

Use a session bound to the intended project. A common workspace conversation without a project uses the legacy General project for newly created tasks.

For direct creation, select the intended project, enter the title and offered fields, and check the created item in Task Detail. New work begins in **Inbox**. Creation does not approve execution or create an active agent assignment.

## Review the brief

Check the goal, description, owner, assignee, scope, acceptance criteria, dates, dependencies, and Task Files. If the task is vague, ask the agent to refine it before execution.

A small useful task might be: “Write a two-page onboarding guide using the attached screenshots, publishable as HTML and PDF, with reviewed links and no product changes.”

The [task-writing guide](/user-guide/task-writing-best-practices) shows a fuller brief.

## Assign and approve

Choose the appropriate assignee. The current task supports a single assignee. When the task is clear enough, approve it by moving it to **Ready** through the permitted control or a later explicit approval request.

Ready can trigger automatic dispatch when the executor and prerequisites are available. If you only want further planning, keep the task in Inbox.

Creating a task, approving its execution, and authorizing external or destructive actions are separate decisions.

## Follow execution

Open Task Detail and review **Current execution**, latest updates, lifecycle, checklist, and next action. **Open session** takes you to the running agent's conversation. Earlier runs remain in Execution history.

If the task is Waiting, supply the required input. If it is Blocked, resolve the recorded obstacle. If you intentionally postpone it, use Paused. Follow allowed lifecycle transitions rather than trying to assign an already-running task to a different executor.

## Review and complete

1. Read the acceptance criteria.
2. Open Deliveries and inspect the actual result.
3. Open Proofs and review the verification.
4. Compare result and proof against each criterion.
5. Accept the task using the permitted completion flow, or provide precise feedback and reopen it.

Agent completion requires official proof. An authorized user can use the supported proof-waiver option, which is recorded in task history. A finished response or checked checklist alone is insufficient.

For follow-up changes to Done work, use **Reopen** and choose an allowed state. Use **Archived** for historical retention when the task no longer belongs in active work.

See [Task Detail](/user-guide/task-detail) for attachment buckets, comments, and execution history.
