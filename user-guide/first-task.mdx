# Create your first task

You can create work from the chat panel or through the dashboard. The recommended path is to start in chat with the agent who should help shape the task.

## Good task request example

```text
Goal: Create a user onboarding guide for AgentDesk.
Output: A published documentation page plus source files.
Context: It should help a first-time user understand workspace, board, chat, agents, and delivery files.
Constraints: Keep it user-friendly; do not include internal runtime details.
Done means: The docs render correctly and are attached to a dashboard task.
```

## What happens next

1. The agent may ask clarifying questions.
2. The request can become a normal dashboard task.
3. New user-requested tasks usually start in **Inbox** unless you explicitly approve execution.
4. When ready, the task can move to execution and be assigned to an agent.
5. Progress, blockers, and outputs should appear on the board and in linked files.

## Task states you will see

| State | Meaning |
| --- | --- |
| **Inbox** | Captured, but not approved or clear enough to execute. |
| **Ready** | Clear enough to execute when an agent is available. |
| **In progress / Active** | An agent is currently working on it. |
| **Waiting** | The system needs your input or an external decision. |
| **Blocked** | Work cannot safely continue. |
| **Done** | Work reached the agreed completion boundary with evidence/output. |
| **Archived** | Closed historical task, not active work. |

## Tips

- Prefer one clear outcome per task.
- Ask for evidence or a delivery file when the output matters.
- If a task becomes too large, ask the agent to split it into subtasks.
- Do not mark work done only because code or text was written; verify the result.
