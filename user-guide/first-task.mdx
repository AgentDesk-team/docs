# Create and review your first task

In AgentDesk, a good task should be visible on the board, assigned to the right person or agent, and clear enough to execute.

For onboarding, the recommended first task is **Sample Task 000**.

## Recommended onboarding request

Send this to your selected agent:

```text
Please assign Sample Task 000 to me and move it to Ready so I can review it before execution.
```

The agent should either create the sample task or update the existing sample task so it is ready for review.

## Review before execution

Before the task runs, open it from the dashboard and check:

| Check | What to look for |
| --- | --- |
| Title | Is it clear what the task is? |
| Status | Is it **Ready**? |
| Owner / assignee | Is it assigned to the right user or agent? |
| Summary | Does it explain the goal? |
| Next action | Is the next action concrete? |
| Output | Is the expected output clear? |
| Scope | Is there anything unexpected or too broad? |

If the task is unclear, ask the agent to fix it before continuing.

## Wait for completion

After review, let the agent complete the task. Watch the status:

- **Ready** means queued for work.
- **In progress / Active** means an agent is working.
- **Waiting** means the agent needs your input.
- **Blocked** means something prevents safe progress.
- **Done** means the output should be ready to review.

## Review the output

When the task is Done:

1. Open **Workspace Management → Files** or **Delivery Files**.
2. Find the Task 000 output.
3. Open or publish the output link.
4. Review the form/page in the browser.
5. Submit feedback.

## For real tasks after onboarding

Use this format:

```text
Goal: What are we trying to achieve?
Output: What should be produced?
Context: What should the agent know?
Constraints: What should not happen?
Done means: How will we know this succeeded?
```

## Important rule

<Warning>
A chat reply is not enough to consider a task done. Always check the task state and output/evidence on the dashboard or in workspace files.
</Warning>
