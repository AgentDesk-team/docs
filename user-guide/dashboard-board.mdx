Open **Projects**, choose a project, and open **Work Items**. Each item represents a tracked AgentDesk task. You can create an item directly with **Add work item**, or ask an agent to create one from a conversation.

## Choose a layout

| Layout | Use it for |
| --- | --- |
| **List** | Scan tasks and grouped work. |
| **Board** | Review work by status or another grouping. |
| **Calendar** | See dated work. |
| **Table** | Compare task properties in rows and columns. |
| **Gantt** | Review scheduled work across time. |

Layouts display the same work records. A layout change does not change task lifecycle. Dates must be recorded for scheduling views to be useful.

## Search, filter, and display

Search by title or identifier. Use the filters for status, priority, assignee, Task Owner, reporter, label, and due-date range. Temporary filters change the current view.

**Display** offers grouping and sub-grouping, visible properties, ordering, and direction. Available grouping includes status, priority, assignee, and label. Use **Clear temporary filters** or **Reset display** to remove choices you no longer need.

Archived work is excluded from ordinary active views. Use **Show archived** or **Archives** when you need historical items.

## Save a view

Open **Views**, choose **Add view** or **Create view**, name it, and save the offered filters and layout configuration. A private view is personal; a shared view can be used by permitted teammates.

Search Views or filter by access to find one later. Only a view's owner can edit or delete it. Saved-view privacy controls the view definition; it does not grant access to tasks a viewer otherwise cannot see.

## Export and custom properties

Use **Export current view (.csv)** from the work item actions to export the current result set.

Use **Custom properties** to define additional fields where permitted, then edit values in Task Detail. The current editor supports types including text, number, date, selection, multi-selection, checkbox, and URL. These fields help describe the work; they do not replace status, assignment, dependencies, or acceptance criteria.

## Understand lifecycle

| Status shown in the UI | Meaning |
| --- | --- |
| **Inbox** | Created, awaiting review and execution approval. |
| **Ready** | Approved and eligible to start; there is no active executor yet. |
| **In Progress** | An active assignment is running. |
| **Waiting** | Waiting for input, a dependency, review, provider, or planned time. |
| **Blocked** | An obstacle must be resolved. |
| **Paused** | Deliberately postponed. |
| **Done** | Completed under the task's verification requirements. |
| **Archived** | Retained as historical work. |

**Waiting** is the displayed label for the pending lifecycle. Older terms such as Drafting spec, Pending approval, and Ready to review are not separate current lifecycle states.

Changing a task to Ready can make it eligible for automatic dispatch. Review scope and assignment before approving it. Only allowed transitions are offered; moving to In Progress requires an assignee and remains subject to server validation.

## Analytics

Open **Analytics** in Work Items to inspect totals, created versus resolved work, status distribution, and assignee workload for the current view. Filters affect this analysis. These project insights are distinct from workspace token usage and billing.
