# Projects

A project groups related work items, sessions, planning, pages, and files. Use it as the scope for a product, initiative, client, or other body of work.

## Create a project

1. Open **Projects** and choose **New project**.
2. Enter its name, identifier, and description.
3. Choose **Create new** for a new project folder, or **Bind existing** and select an existing folder inside WS Files.
4. Review the offered shared instructions in **PROJECT.md**.
5. Create the project and check the result.

When binding an existing folder, review the current PROJECT.md before saving. Project creation is subject to permissions and plan limits; a quota error means you need to review those limits, not retry with a different hidden route.

A project folder can contain source repositories and task folders. Binding a folder does not automatically clone a repository.

## Maintain project instructions

Open **Edit project** or the instruction editor in **Overview** to maintain the description and PROJECT.md. The current Edit project form keeps the name, identifier, and bound folder read-only.

Use PROJECT.md for stable context such as goals, product language, repository conventions, constraints, and acceptance expectations. Agents in a bound project receive the current project context during their work. Common workspace sessions do not inherit a project's document merely because you browsed that project.

If a document fails validation or another editor changed it, read the error, reload the latest content, and review your changes before saving again. Missing instructions do not remove the project binding.

## Navigate a project

| Section | Purpose |
| --- | --- |
| **Overview** | Description, instructions, project details, activity, and insights. |
| **Work Items** | Track, filter, and review tasks. |
| **Intake** | Review incoming Inbox work. |
| **Cycles** | Plan a dated delivery period. |
| **Modules** | Group a milestone or related outcome. |
| **Views** | Save and reopen filters and layout choices. |
| **Pages** | Project documents, subject to page and Wiki availability. |
| **Archives** | Find archived work items and pages and restore permitted records. |

See [Work Items and views](/user-guide/dashboard-board) and [Project planning](/user-guide/project-planning) for the detailed work flows. Pages and Wiki remain [high level](/user-guide/skills-wiki-desktop) in this guide.

## Archive or restore a project

Use the project's menu to archive it when it should leave the active list. Open **Archived** on Projects home to find it and choose **Restore project** when permitted.

Archival changes how the project is listed. It is not an instruction to delete its source repositories or files. Check active work before archiving.
